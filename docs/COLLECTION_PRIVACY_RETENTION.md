# Collection privacy and retention

- Standard collection sends versioned features and quality/location evidence,
  never raw sensor arrays.
- Controlled raw data requires explicit device authorization and is stored in
  a private object bucket. Presigned URLs are short-lived and object keys are
  generated by the server under vehicle/profile prefixes.
- Raw sensor objects contain monotonic deltas, not account, installation,
  session, route, city, or geographic identifiers.
- Dataset exports replace installation UUIDs with salted pseudonyms and fail
  closed when `COLLECTION_EXPORT_PSEUDONYM_SALT` is absent.
- Quarantined sessions are diagnostic-only and excluded from training exports.
- `npm run collection:cleanup` is dry-run by default. Add `-- --apply` only in
  an authorized scheduled job. It deletes eligible object bytes but retains
  metadata/audit rows and marks them `DELETED`.
- Cancelling or hard-rejecting an incomplete session marks its objects
  `DELETE_PENDING`. Configure raw retention with
  `COLLECTION_RAW_RETENTION_DAYS`; changes require a documented policy review.
- Account deletion/consent-revocation integration must mark pending objects for
  deletion before controlled collection is offered outside the research
  cohort.
